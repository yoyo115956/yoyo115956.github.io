> 流水线是提升处理器吞吐量的核心技术。本文系统梳理五级流水线的设计、三类冒险及其硬件解决方案。

# 一、流水线基本概念

流水线（Pipeline）将指令执行拆分为多个**独立阶段**，让不同阶段同时处理不同指令，从而提高吞吐量。

类比洗衣：不等一件衣服洗烘完毕再洗下一件，而是洗衣机洗、烘干机烘、折叠同时进行。

## 1.1 五个阶段

| 阶段 | 缩写 | 功能 |
|------|------|------|
| 取指 | IF | 根据 PC 从指令内存取出指令 |
| 译码 | ID | 解析操作码、读取寄存器文件 |
| 执行 | EX | ALU 运算或计算有效地址 |
| 访存 | MEM | 读写数据存储器 |
| 写回 | WB | 将结果写回寄存器文件 |

## 1.2 流水线寄存器

相邻阶段之间插入**流水线寄存器**，存储当前阶段产生的中间结果，在时钟上升沿锁存并传递到下一阶段。

```
[IF/ID reg] → [ID/EX reg] → [EX/MEM reg] → [MEM/WB reg]
```

理想情况下，每个时钟周期完成一条指令（CPI = 1）。

# 二、数据冒险与解决方案

## 2.1 RAW（读写相关）

最常见的数据冒险：后续指令需要读取前续指令**尚未写回**的结果。

```assembly
add x1, x2, x3   # x1 = x2 + x3（EX 阶段产生结果）
sub x4, x1, x5   # 需要 x1，但 x1 还没写回
```

### 解决方案一：数据前递（Forwarding / Bypassing）

将 EX/MEM 或 MEM/WB 寄存器中的结果**直接转发**给 EX 阶段的 ALU 输入，无需等待写回。

```
检测条件（EX-EX 前递）：
  IF (EX/MEM.RegWrite AND EX/MEM.Rd ≠ 0
      AND EX/MEM.Rd == ID/EX.Rs1)
  THEN ForwardA = 10  // 从 EX/MEM 前递
```

前递可以解决大多数 RAW 冒险，但对 **Load-Use 冒险**无效。

### 解决方案二：插入气泡（Stall）

Load-Use 冒险：Load 指令在 MEM 阶段才得到数据，而下一条指令在 EX 阶段就需要它。

硬件检测到此类冒险时，**插入一个 NOP（气泡）**，让流水线暂停一个周期：

```assembly
lw  x1, 0(x2)    # MEM 阶段才有 x1
add x3, x1, x4   # 必须 stall 一周期
```

# 三、控制冒险与分支预测

## 3.1 分支问题

条件分支指令（如 `beq`）在 EX 阶段才能确定是否跳转，此时 IF、ID 阶段已经取了后续指令——如果分支发生跳转，这些指令需要被**冲刷（flush）**。

## 3.2 静态预测策略

| 策略 | 描述 | 场景 |
|------|------|------|
| 预测不跳转 | 总按顺序执行 | 简单实现，正确率约 50-60% |
| 预测跳转 | 总执行分支目标 | 循环场景效果好 |
| BTFN | 向后分支预测跳转，向前预测不跳转 | 利用循环特性 |

## 3.3 动态预测：两位饱和计数器

使用 2 位状态机追踪分支历史：

```
强不跳(00) ←→ 弱不跳(01) ←→ 弱跳转(10) ←→ 强跳转(11)
```

- 预测阈值：`状态 >= 10` 则预测跳转
- 需要一次"错误"才会改变预测方向，对循环体分支非常有效

## 3.4 延迟槽（Delay Slot）

RISC 早期设计（MIPS）中，分支后的一条指令**无论是否跳转都会执行**，编译器负责在此位置填入有用指令（或 NOP）。现代 ISA（RISC-V）已不使用延迟槽。

# 四、结构冒险

当多条指令**同时竞争同一硬件资源**时发生结构冒险。

常见场景：
- 指令和数据共用同一块存储器（冯诺依曼架构）→ 解决：哈佛架构（分离 I-Cache 和 D-Cache）
- 单端口寄存器文件，ID 与 WB 同时访问 → 解决：双端口寄存器文件，或 WB 先写（前半周期写回，后半周期读）

# 五、流水线性能分析

## 5.1 加速比

$$
\text{加速比} = \frac{\text{非流水线执行时间}}{\text{流水线执行时间}} = \frac{N \times k \times t}{(k + N - 1) \times t}
$$

其中 $N$ 为指令数，$k$ 为流水线级数，$t$ 为单级时延。当 $N \gg k$ 时，加速比趋近于 $k$。

## 5.2 实际 CPI

$$
\text{CPI}_{\text{实际}} = \text{CPI}_{\text{理想}} + \text{结构停顿} + \text{数据停顿} + \text{控制停顿}
$$

## 5.3 设计权衡

- **更深的流水线**：更高主频，但分支预测错误代价更大（Pentium 4 有 31 级流水线）
- **更宽的流水线**：超标量，每周期发射多条指令，CPI < 1

# 六、Verilog 实现要点

实现五级流水线处理器的关键模块：

```verilog
// 流水线寄存器示例（IF/ID）
module if_id_reg (
    input  wire        clk, rst, stall, flush,
    input  wire [31:0] if_pc, if_instr,
    output reg  [31:0] id_pc, id_instr
);
    always @(posedge clk) begin
        if (rst || flush) begin
            id_pc    <= 32'b0;
            id_instr <= 32'h00000013; // NOP: addi x0,x0,0
        end else if (!stall) begin
            id_pc    <= if_pc;
            id_instr <= if_instr;
        end
    end
endmodule
```

关键设计点：
1. stall 信号：PC 和 IF/ID 寄存器保持不变，ID/EX 寄存器填入 NOP
2. flush 信号：清空 IF/ID、ID/EX 寄存器（用于控制冒险）
3. 前递单元：检测寄存器编号，选择正确的数据来源
