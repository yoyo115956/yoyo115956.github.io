> 存储墙（Memory Wall）是现代处理器最大的性能瓶颈。Cache 是弥合处理器速度与内存速度差距的核心机制。

# 一、为什么需要 Cache

处理器与 DRAM 之间的速度差距持续扩大：

| 存储层次 | 典型延迟 | 典型容量 |
|----------|----------|----------|
| 寄存器 | < 1 ns | ~1 KB |
| L1 Cache | 1-4 cycles (~0.5 ns) | 32-64 KB |
| L2 Cache | 10-20 cycles (~5 ns) | 256 KB - 1 MB |
| L3 Cache | 30-50 cycles (~15 ns) | 4-64 MB |
| DRAM | 100-300 cycles (~60 ns) | 4-64 GB |

Cache 利用程序的**局部性原理**解决这一问题：
- **时间局部性**：刚访问过的数据很可能很快再次访问（循环变量）
- **空间局部性**：访问某个地址后，其附近地址也很可能被访问（数组遍历）

---

# 二、Cache 基本结构

## 2.1 Cache Line（缓存行）

Cache 以**行（Line / Block）**为单位在 Cache 和内存之间传输数据，典型大小为 64 字节。

每个 Cache Line 包含：
- **有效位（Valid bit）**：该行是否有效
- **标记（Tag）**：存储对应内存地址的高位部分
- **数据（Data）**：实际缓存的数据块

## 2.2 地址分解

对于 32 位地址、64 字节 Cache Line、N 路组相联、共 S 组的 Cache：

$$
\text{地址} = \underbrace{\text{Tag}}_{\text{高位}} \mid \underbrace{\text{Index（组号）}}_{\log_2 S \text{ 位}} \mid \underbrace{\text{Offset（块内偏移）}}_{\log_2 64 = 6 \text{ 位}}
$$

# 三、Cache 映射策略

## 3.1 直接映射（Direct Mapped）

每个内存块只能映射到 Cache 中**固定的一行**。

- 优点：硬件简单，查找速度快
- 缺点：冲突缺失（Conflict Miss）多，当两个频繁访问的地址映射到同一行时，互相驱逐

## 3.2 全相联（Fully Associative）

内存块可以放到 Cache 中**任意一行**。

- 优点：冲突缺失最少
- 缺点：每次查找需要与所有 Tag 并行比较，硬件复杂，功耗高

## 3.3 组相联（Set Associative）⭐

折中方案：Cache 分为 $S$ 组，每组 $N$ 路（N-Way Set Associative）。

内存块根据 Index 定位到**固定的组**，但在该组内**任意一路**均可存放。

典型配置：
- L1 Cache：4 路或 8 路组相联
- L2 Cache：8 路或 16 路组相联
- LLC（Last Level Cache）：16 路组相联

# 四、替换策略

当 Cache 组已满，需要驱逐一行时的决策：

| 策略 | 描述 | 优点 |
|------|------|------|
| LRU（最近最少使用） | 替换最长时间未访问的行 | 最接近最优，实现合理 |
| FIFO（先进先出） | 替换最早进入的行 | 简单，但性能不如 LRU |
| Random（随机） | 随机选择替换行 | 极简，可避免某些 LRU 的抖动问题 |
| PLRU（伪 LRU） | 用二叉树近似 LRU | 硬件开销远小于精确 LRU |

# 五、写策略

## 5.1 写命中时

| 策略 | 行为 | 特点 |
|------|------|------|
| 写直达（Write-Through） | 同时写 Cache 和内存 | 简单，一致性好，带宽压力大 |
| 写回（Write-Back） | 只写 Cache，驱逐时才写内存 | 减少内存带宽，需要脏位（Dirty bit） |

## 5.2 写缺失时

| 策略 | 行为 |
|------|------|
| 写分配（Write-Allocate） | 先把块调入 Cache，再写（配合写回使用） |
| 非写分配（No-Write-Allocate） | 直接写内存，不调入 Cache（配合写直达使用） |

# 六、Cache 缺失类型（3C 模型）

| 类型 | 英文 | 原因 | 解决方向 |
|------|------|------|----------|
| 强制缺失 | Compulsory Miss | 首次访问，Cache 为空 | 预取（Prefetching） |
| 容量缺失 | Capacity Miss | Cache 容量不够 | 增大 Cache |
| 冲突缺失 | Conflict Miss | 多路映射冲突 | 提高相联度 |

还有一类：
- **一致性缺失（Coherence Miss）**：多核场景下，其他核修改了数据 → 需要缓存一致性协议（MESI 等）

# 七、性能指标

## 7.1 平均内存访问时间（AMAT）

$$
\text{AMAT} = \text{Hit Time} + \text{Miss Rate} \times \text{Miss Penalty}
$$

多级 Cache：

$$
\text{AMAT} = T_{L1} + m_{L1} \times (T_{L2} + m_{L2} \times T_{MEM})
$$

## 7.2 优化方向

- 减少 Hit Time：更小的 Cache，更少路数，流水化 Tag 检查
- 减少 Miss Rate：更大的 Cache，更高相联度，预取
- 减少 Miss Penalty：多级 Cache，关键字优先返回（Critical Word First）

# 八、代码优化示例

```c
// 矩阵转置 —— Cache 不友好版本
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        B[j][i] = A[i][j];  // B 的写访问不连续，大量 Cache Miss

// Cache 友好版本：分块（Blocking / Tiling）
int BLOCK = 32;
for (int i = 0; i < N; i += BLOCK)
    for (int j = 0; j < N; j += BLOCK)
        for (int ii = i; ii < i+BLOCK; ii++)
            for (int jj = j; jj < j+BLOCK; jj++)
                B[jj][ii] = A[ii][jj]; // 在小块范围内保持局部性
```

分块将 Cache Miss 率降低数倍，是 GEMM（矩阵乘法）优化的基础手段。
