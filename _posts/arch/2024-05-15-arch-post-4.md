> 乱序执行（Out-of-Order Execution）是现代高性能处理器的核心技术，本文系统介绍 Tomasulo 算法和 ROB 的工作原理。

# 一、为什么需要乱序执行

顺序执行处理器中，一旦某条指令因数据未就绪而 stall，后续所有指令都被阻塞，即使后续指令与当前 stall 指令毫无关联。

```assembly
lw   x1, 0(x2)    # 访存延迟 100+ 周期
add  x3, x1, x4   # 依赖 x1，必须等待
mul  x5, x6, x7   # 与 x1 无关，但仍被阻塞！
```

乱序执行的思路：**按数据就绪顺序执行，按程序顺序提交**，对程序语义完全透明。

# 二、Tomasulo 算法

Tomasulo 算法（1967 年，IBM 360/91）是乱序执行的经典实现，核心机制是**保留站（Reservation Station）+ 公共数据总线（CDB）**。

## 2.1 核心数据结构

### 保留站（Reservation Station, RS）
每个执行单元前配备若干保留站槽位，存储等待执行的指令：

| 字段 | 说明 |
|------|------|
| Busy | 该槽位是否被占用 |
| Op | 操作类型（ADD, MUL, LOAD...） |
| Vj, Vk | 源操作数的值（已就绪时） |
| Qj, Qk | 产生源操作数的保留站编号（未就绪时）|
| A | 内存地址（Load/Store 指令） |

### 寄存器状态表（Register Status Table）
记录每个寄存器由哪个保留站负责写入（或已有值）。

## 2.2 三个阶段

**Issue（发射）**：从指令队列取出指令，分配保留站槽位
- 检查操作数寄存器：已就绪则直接读值（Vj/Vk），未就绪则记录产生它的保留站编号（Qj/Qk）
- 更新寄存器状态表，标记该寄存器将由此保留站写入

**Execute（执行）**：当 Qj = Qk = 0（所有操作数就绪），进入执行单元
- Load/Store 指令需先计算有效地址

**Write Result（写结果）**：通过 CDB 广播结果
- 所有等待该结果的保留站立即获取数据（Qj/Qk 清零，填入 Vj/Vk）
- 寄存器文件更新

## 2.3 示例

```assembly
lw  x1, 0(x2)   # RS1
add x3, x1, x4  # RS2：Qj=RS1（等待 x1），Vk=x4
mul x5, x3, x6  # RS3：Qj=RS2（等待 x3），Vk=x6
sub x7, x4, x8  # RS4：Vj=x4，Vk=x8（立即执行！）
```

`sub` 指令与 `lw/add/mul` 无关，可以立即执行，无需等待。

# 三、重排序缓冲区（Reorder Buffer, ROB）

Tomasulo 算法本身无法处理**精确异常**（指令执行出错时需要回退到精确状态）和**分支预测失败**的恢复。ROB 解决了这一问题。

## 3.1 ROB 结构

ROB 是一个循环队列，按程序顺序保存所有已发射但未提交的指令：

| 字段 | 说明 |
|------|------|
| Entry | 循环序号 |
| Instruction | 指令类型 |
| Dest | 目的寄存器编号 |
| Value | 计算结果（执行完成后填入）|
| Ready | 结果是否就绪 |

## 3.2 指令生命周期（含 ROB）

```
Fetch → Issue（分配 ROB 条目）→ Execute → Write Result（写入 ROB）
→ Commit（按序从 ROB 头部提交到架构寄存器文件）
```

**关键点**：
- 执行结果先写入 ROB，不直接写架构寄存器
- 只有 ROB 头部指令 Ready 时才提交（保证顺序）
- 分支预测失败：清空 ROB 和保留站，从正确路径重新取指
- 异常：同样清空 ROB，处理器回到异常前的精确状态

## 3.3 寄存器重命名

ROB 实现了**隐式寄存器重命名**：多条指令写同一逻辑寄存器时，每条指令对应不同的 ROB 条目，消除了 WAW（写写相关）和 WAR（先写后读）伪相关。

物理寄存器文件（Physical Register File, PRF）方案是更常见的工业实现：
- 逻辑寄存器 → 物理寄存器的映射表（RAT / Register Alias Table）
- 更大的物理寄存器池（如 192 个物理寄存器对应 16 个逻辑寄存器）

# 四、超标量处理器整体流水线

现代高性能超标量乱序处理器（如 RISC-V OoO core）的典型流水线：

```
┌─────────────────────────────────────────────────────────┐
│  Fetch → Decode → Rename → Dispatch → Issue Queue      │
│                                              ↓          │
│                               ┌─── ALU ─────┤          │
│                               ├─── MUL ─────┤          │
│                               ├─── Load ────┤          │
│                               └─── Store ───┤          │
│                                              ↓          │
│                              Writeback → ROB → Commit  │
└─────────────────────────────────────────────────────────┘
```

## 关键设计参数（以业界典型配置为例）

| 参数 | 典型值 |
|------|--------|
| 发射宽度 | 4-8 条/周期 |
| ROB 容量 | 128-512 条目 |
| 物理寄存器数量 | 160-256 |
| 保留站总容量 | 60-100 条目 |
| Load/Store Queue | 32-72 条目 |

# 五、性能分析

乱序执行能够隐藏的延迟受限于**窗口大小**（ROB 容量）。

$$
\text{可隐藏延迟} \approx \frac{\text{ROB 容量}}{\text{IPC}}
$$

例：ROB 容量 256，IPC = 4，可隐藏 ~64 周期的延迟（足以覆盖 L2 Cache Miss）。
