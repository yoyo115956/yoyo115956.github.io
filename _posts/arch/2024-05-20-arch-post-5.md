> 现代处理器流水线深达 14-20 级，分支预测失败意味着 10-20 周期的性能损失。准确的分支预测是高性能处理器的关键。

# 一、分支预测的重要性

假设处理器流水线深度为 15 级，分支在第 10 级解析：
- 预测正确：无惩罚，吞吐量正常
- 预测失败：冲刷 10 条错误取入的指令，损失 10 周期

若程序中 20% 的指令是分支，分支预测准确率从 90% 提升到 99%：

$$
\text{CPI 改善} = 0.2 \times (0.10 - 0.01) \times 10 \approx 0.18 \text{ 周期/指令}
$$

这是相当显著的提升。

# 二、预测器发展史

## 2.1 静态预测（第一代）

- 编译器在指令中嵌入 hint bit
- 向后分支预测跳转（利用循环特性），向前分支预测不跳转
- 准确率约 65-75%

## 2.2 两位饱和计数器（BHT）

**Branch History Table（分支历史表）**：以分支 PC 的低位为索引，查表得到 2 位饱和计数器。

```
状态转移：
  强不跳(00) ←T← 弱不跳(01) ←T← 弱跳转(10) ←T← 强跳转(11)
          →NT→           →NT→            →NT→

  T = Taken（跳转），NT = Not Taken（不跳转）
  当状态 >= 10 时预测跳转
```

优点：对循环分支非常有效（循环末尾的退出只有一次预测错误）。
缺点：仅利用单条分支的历史，忽略了分支间的相关性。

## 2.3 局部历史预测器

每个分支维护一个**本地历史寄存器（PHR）**，记录该分支最近 k 次的跳转/不跳转结果（每位 1=Taken, 0=Not-Taken）。

```
分支 PC → PHR (历史模式) → 2-bit 计数器表
```

例：某分支历史为 `101010...`（隔一次跳转），局部历史预测器可以完美预测。

## 2.4 全局历史预测器（GShare）

使用**全局历史寄存器（GHR）**记录所有分支的最近 k 次结果，与分支 PC 做异或，索引 PHT（模式历史表）。

```
GHR XOR PC[低位] → PHT（2-bit 计数器数组）
```

**GShare 优点**：利用不同分支间的相关性，准确率通常优于局部历史。

**Tournament 预测器**：结合局部和全局预测器，用一个"选择器"动态决定用哪个预测器。Alpha 21264 使用了此方案，准确率约 97%。

# 三、TAGE 预测器

TAGE（TAgged GEometric history length predictor）是目前学术界和工业界最先进的分支预测方案之一，被多款高性能处理器采用。

## 3.1 核心思想

使用**多个具有不同历史长度的表**，每个表存储 Tag 和预测计数器：

```
T0（基础预测器，无 Tag）
T1（历史长度 L1，Tag 检查）
T2（历史长度 L2 > L1，Tag 检查）
T3（历史长度 L3 > L2，Tag 检查）
T4（历史长度 L4 > L3，Tag 检查）

历史长度通常呈几何级数：L1=5, L2=11, L3=23, L4=45...
```

**预测过程**：
1. 所有表并行查找
2. 选择**最长历史且 Tag 匹配**的表作为最终预测（优先使用最精确的上下文）
3. 若无 Tag 匹配，使用 T0 基础预测器

## 3.2 优势

| 特性 | 说明 |
|------|------|
| 多历史长度 | 捕获短期和长期的分支相关性 |
| Tag 匹配 | 减少别名干扰（Aliasing）|
| 几何历史增长 | 用较少存储覆盖宽范围的历史长度 |
| 理论上界 | 已被证明接近最优预测上界 |

实测准确率：在 SPEC CPU 基准测试中，TAGE 可达 **98-99.5%** 的准确率。

# 四、间接分支预测（BTB + RAS）

普通分支预测器只预测**是否跳转**，还需要预测**跳转目标地址**。

## 4.1 分支目标缓冲（BTB）

**Branch Target Buffer**：缓存最近执行过的分支的目标地址。

```
PC → BTB → 预测目标地址（下一周期 IF 直接取该地址）
```

## 4.2 间接跳转预测

函数指针调用、虚函数调用等间接分支，目标地址在运行时才确定。

**Indirect Branch Predictor（ITTAGE）**：类似 TAGE，专门预测间接分支目标。

## 4.3 返回地址栈（RAS）

函数返回（`ret` / `jalr ra`）的目标地址是调用时的 PC+4。

**Return Address Stack（RAS）**：硬件维护的小型栈：
- 执行 `call`：将 PC+4 压栈
- 执行 `ret`：从栈顶弹出预测目标

RAS 深度通常为 16-64，对函数调用/返回的预测准确率接近 100%。

# 五、投机执行与安全（Spectre）

分支预测错误时，投机执行的指令会被清除，但**已经影响了 Cache 状态**。

Spectre 攻击利用这一点：
1. 训练分支预测器使其预测错误
2. 投机执行访问越界内存
3. 通过 Cache 计时侧信道泄露秘密数据

这是体系结构安全领域的重要研究方向，现代处理器通过 IBRS、retpoline 等软硬件联合方案缓解。

# 六、小结：各预测器对比

| 预测器 | 存储需求 | 准确率 | 适用场景 |
|--------|----------|--------|----------|
| 静态预测 | 0 | ~65% | 极简实现 |
| 两位计数器 | 低 | ~85% | 嵌入式处理器 |
| GShare | 中 | ~93% | 经典设计 |
| Tournament | 中高 | ~97% | Alpha 21264 时代 |
| TAGE | 高 | ~99% | 现代高性能处理器 |
