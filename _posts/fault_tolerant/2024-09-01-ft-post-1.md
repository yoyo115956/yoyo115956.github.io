> 容错计算（Fault-Tolerant Computing）研究如何在硬件故障存在的情况下保证系统正确运行，是航天、服务器、汽车电子等高可靠场景的核心技术。

# 一、为什么需要容错

## 1.1 硬件故障无处不在

现代芯片工作在复杂的物理环境中，面临多种故障威胁：

| 故障来源 | 典型场景 |
|----------|----------|
| 宇宙射线 | 卫星、航天器（单粒子事件）|
| 工艺缺陷 | 芯片生产良率、老化失效 |
| 电磁干扰 | 工业环境、汽车电子 |
| 电源噪声 | 数据中心、边缘计算 |
| 温度变化 | 运行时动态温度波动 |

**DRAM Soft Error Rate**：服务器中每 GB DRAM 每年约发生 1-10 次软错误（位翻转）。

## 1.2 可靠性需求驱动

| 应用领域 | 可靠性要求 |
|----------|------------|
| 航天 / 核设施 | 99.999% 以上 |
| 医疗设备 | 极高，涉及人身安全 |
| 汽车功能安全（ISO 26262）| ASIL-D：随机硬件故障率 < 10⁻⁸ /h |
| 金融服务器 | 5-9（99.999%）可用性 |
| 消费电子 | 较宽松 |

# 二、故障模型分类

## 2.1 按持续时间分类

| 类型 | 英文 | 说明 | 示例 |
|------|------|------|------|
| 永久故障 | Permanent Fault | 持续存在，不可恢复 | 工艺缺陷、电路短路 |
| 间歇故障 | Intermittent Fault | 有时出现有时消失 | 松散焊点、时序裕量不足 |
| 软错误 | Soft Error / Transient | 一次性，不影响硬件 | 宇宙射线导致的位翻转 |

## 2.2 按影响范围分类

| 类型 | 说明 |
|------|------|
| 单点故障（Single Point of Failure, SPOF）| 一个组件故障导致整个系统失效 |
| 单粒子翻转（SEU）| 单个存储位被翻转 |
| 单粒子多位翻转（MBU）| 一个粒子翻转多个相邻位 |
| 单粒子功能中断（SEFI）| 扰乱控制逻辑，影响功能正确性 |

## 2.3 故障 → 错误 → 失效链

```
故障（Fault）
   ↓ 激活（Activation）
错误（Error）      ← 故障在系统状态中的错误表现
   ↓ 传播（Propagation）
失效（Failure）    ← 错误传播到系统输出，被外部观测到
```

容错技术的目标：**阻断故障到错误、错误到失效的传播链**。

# 三、可靠性量化指标

## 3.1 基本指标

$$
\text{MTTF（平均无故障时间）} = \int_0^\infty R(t) \, dt
$$

$$
\text{MTTR（平均修复时间）}：\text{从故障发生到修复完成的平均时间}
$$

$$
\text{MTBF（平均故障间隔）} = \text{MTTF} + \text{MTTR}
$$

$$
\text{可用性}(A) = \frac{\text{MTTF}}{\text{MTTF} + \text{MTTR}}
$$

## 3.2 可靠性函数

对于指数分布的故障率 $\lambda$（常数故障率假设）：

$$
R(t) = e^{-\lambda t}
$$

$$
\text{MTTF} = \frac{1}{\lambda}
$$

## 3.3 串联与并联系统

**串联系统**（所有组件都正常，系统才正常）：

$$
R_{series}(t) = \prod_{i=1}^n R_i(t)
$$

**并联系统**（至少一个组件正常，系统即正常）：

$$
R_{parallel}(t) = 1 - \prod_{i=1}^n (1 - R_i(t))
$$

# 四、容错技术分类

## 4.1 硬件冗余

| 技术 | 说明 | 开销 |
|------|------|------|
| TMR（三模冗余）| 三份硬件，多数投票 | 面积 ×3 |
| DMR（双模冗余）| 两份硬件，比较结果 | 面积 ×2，只能检测不能纠错 |
| Standby Spare | 备用模块，故障时切换 | 面积开销 + 切换时间 |
| ECC 内存 | 错误检测与纠正编码 | 面积 ~12%（SECDED）|

## 4.2 信息冗余

| 技术 | 说明 |
|------|------|
| 奇偶校验 | 1 位，检测单比特错误 |
| SECDED（汉明码）| 检测 2 位，纠正 1 位 |
| Reed-Solomon 码 | 多位错误纠正，用于存储系统 |
| CRC | 帧错误检测，用于通信 |

## 4.3 时间冗余

- **重复执行**：同一计算执行多次，比较结果
- **回滚（Rollback）**：保存检查点，出错时恢复
- **前向恢复**：通过冗余信息直接恢复正确状态

## 4.4 软件容错

- **N 版本编程（NVP）**：多个独立团队开发相同功能，结果投票
- **恢复块（Recovery Block）**：主版本失败时切换到备份版本
- **算法容错（ABFT）**：在算法层面加入冗余计算

# 五、故障注入（Fault Injection）

验证容错机制是否有效的关键手段：

| 方法 | 说明 | 优缺点 |
|------|------|--------|
| 硬件故障注入 | 物理针刺、辐射实验 | 真实但昂贵 |
| 仿真故障注入 | 在 gem5/RTL 仿真中翻转位 | 快速可控，常用 |
| 软件实现的故障注入（SWIFI）| 通过写内存/寄存器注入 | 低成本，只能注入软错误 |

```python
# gem5 中的故障注入示例（翻转某个寄存器的某一位）
class BitFlipEvent(m5.SimObject):
    # 在仿真时钟 1000000 时，翻转 cpu 的整数寄存器 x5 的第 3 位
    event_time = 1000000  # 皮秒
    register = 'x5'
    bit_position = 3
```

# 六、功能安全标准简介

**ISO 26262**（汽车电子功能安全）定义了四个 ASIL 等级（A-D），ASIL-D 最严格：

- 要求对随机硬件故障的检测率 > 99%
- 要求残余故障率 < 10⁻⁸/h（PMHF 指标）
- 强制要求独立安全监控器（Safety Monitor）

**IEC 61508**（工业功能安全）：用于工业控制、医疗设备。

**DO-254**（机载设备硬件）：航空电子设备硬件设计标准。

这些标准定义了容错设计的**最低要求**，是高可靠芯片设计不可绕过的规范体系。
