> 硬件冗余是最直接的容错手段。本文深入介绍 TMR（三模冗余）的设计与实现，以及 ECC 内存的纠错原理。

# 一、三模冗余（TMR）

## 1.1 基本原理

TMR（Triple Modular Redundancy）使用**三份相同的硬件模块并联**，结果通过**多数投票器（Voter）**决定：

```
         ┌─────────┐
Input ──→│ Module A├──→ ┐
         └─────────┘    │
         ┌─────────┐    ├──→ Voter ──→ Output
Input ──→│ Module B├──→ ┤
         └─────────┘    │
         ┌─────────┐    │
Input ──→│ Module C├──→ ┘
         └─────────┘
```

投票逻辑：
- A=B=C=1 → 输出 1
- A=B=1, C=0 → 输出 1（C 故障）
- 任意两模块一致 → 取多数值

**特点**：
- 可以**自动纠正**单个模块的故障（容忍 1/3 故障）
- 面积开销约 ×3，功耗开销约 ×3
- Voter 本身不冗余，是单点故障（可进一步对 Voter 冗余）

## 1.2 Verilog 实现

```verilog
// 组合逻辑投票器
module voter_1bit (
    input  a, b, c,
    output y
);
    assign y = (a & b) | (b & c) | (a & c);
endmodule

// 多位投票器
module voter #(parameter N = 32) (
    input  [N-1:0] a, b, c,
    output [N-1:0] y
);
    genvar i;
    generate
        for (i = 0; i < N; i = i + 1) begin : voter_bits
            voter_1bit v (
                .a(a[i]), .b(b[i]), .c(c[i]),
                .y(y[i])
            );
        end
    endgenerate
endmodule

// TMR 寄存器（带故障检测）
module tmr_reg #(parameter N = 32) (
    input             clk, rst,
    input  [N-1:0]    d,
    output [N-1:0]    q,
    output            error_flag   // 检测到至少一个模块不一致
);
    reg [N-1:0] q_a, q_b, q_c;
    
    always @(posedge clk or posedge rst) begin
        if (rst) begin
            q_a <= 0; q_b <= 0; q_c <= 0;
        end else begin
            q_a <= d; q_b <= d; q_c <= d;
        end
    end
    
    // 投票输出
    voter #(N) v (.a(q_a), .b(q_b), .c(q_c), .y(q));
    
    // 任何不一致都触发 error_flag
    assign error_flag = |(q_a ^ q_b) | |(q_b ^ q_c);
endmodule
```

## 1.3 部分 TMR（PTMR）

对整个设计做完整 TMR 代价太高，实际中常用**部分冗余**：
- 只对**关键路径**（控制寄存器、状态机）做 TMR
- 数据通路使用 ECC 保护
- 根据 FMEA（故障模式与影响分析）确定优先级

# 二、双模冗余（DMR）与故障检测

DMR 只能**检测**故障，不能自动纠错：

```verilog
module dmr_checker #(parameter N = 32) (
    input [N-1:0] a, b,
    output        mismatch
);
    assign mismatch = (a !== b);  // 使用 !== 包含 X 比较
endmodule
```

DMR 常用于：
- 实时检测计算错误，触发系统重置或报警
- 与软件协同：检测到错误时触发异常处理

# 三、汉明码（Hamming Code）与 SECDED

## 3.1 SECDED 原理

**SECDED**（Single Error Correction, Double Error Detection）是 ECC 内存的标准编码方案：
- 每 64 位数据增加 8 位校验位（共 72 位存储）
- 可以**纠正 1 位错误**，**检测 2 位错误**

## 3.2 奇偶校验矩阵

对于 n 个数据位，需要 r 个校验位，满足：

$$
2^r \geq n + r + 1
$$

对 64 位数据：$2^7 = 128 \geq 64 + 7 + 1 = 72$，所以需要 7 位。加上全局奇偶位共 8 位。

## 3.3 编码与解码

```verilog
// SECDED 编码器（8 数据位示例）
module secded_encode (
    input  [7:0]  data,
    output [12:0] codeword  // 8 数据 + 4 汉明 + 1 全局奇偶
);
    // 汉明码位置：1, 2, 4, 8（2 的幂次）为校验位
    // 数据位填入其余位置
    
    // 校验位计算
    wire p1 = data[0] ^ data[1] ^ data[3] ^ data[4] ^ data[6];
    wire p2 = data[0] ^ data[2] ^ data[3] ^ data[5] ^ data[6];
    wire p4 = data[1] ^ data[2] ^ data[3] ^ data[7];
    wire p8 = data[4] ^ data[5] ^ data[6] ^ data[7];
    
    // 全局奇偶位（SECDED 的 "D" 来源）
    wire p_global = ^data ^ p1 ^ p2 ^ p4 ^ p8;
    
    assign codeword = {p_global, p8, p4, data[7:4], p2, data[3:1], p1, data[0]};
endmodule

// SECDED 解码器
module secded_decode (
    input  [12:0] codeword,
    output [7:0]  data,
    output        single_error,   // 检测并纠正了 1 位错误
    output        double_error,   // 检测到 2 位错误（无法纠正）
    output        no_error
);
    // 计算症状（syndrome）：重新计算所有校验位，与收到的异或
    wire s1 = ...;  // 详细实现省略
    wire s2 = ...;
    wire s4 = ...;
    wire s8 = ...;
    
    wire [3:0] syndrome = {s8, s4, s2, s1};
    wire p_global_check = ^codeword;  // 全局奇偶检查
    
    assign no_error      = (syndrome == 4'b0) && !p_global_check;
    assign single_error  = (syndrome != 4'b0) && p_global_check;
    assign double_error  = (syndrome != 4'b0) && !p_global_check;
    
    // 纠正：翻转 syndrome 指示的位
    // 输出纠正后的数据
endmodule
```

# 四、ECC 在存储系统中的应用

## 4.1 DRAM ECC

| 配置 | 数据宽度 | ECC 位 | 能力 |
|------|----------|--------|------|
| SECDED | 64 bit | 8 bit | 纠 1 位，检 2 位 |
| ChipKill | 64 bit | 16 bit | 容忍整块 DRAM 芯片故障 |
| 双设备数据纠正（DDDC）| 64 bit | 32 bit | 容忍两块芯片同时故障 |

**Intel DIMM ECC**：标准服务器内存使用 72 位 DIMM（64 数据 + 8 ECC），每次内存访问硬件自动完成编解码，对软件透明。

## 4.2 SRAM/寄存器文件 ECC

处理器内部寄存器文件、Cache 也普遍使用 ECC：

```
L1 Cache Tag：奇偶校验（检测即可，命中/缺失都可恢复）
L1 Cache Data：SECDED（需要纠正，否则数据损坏）
寄存器文件：奇偶 + 重新执行，或 SECDED
ROB 条目：奇偶校验 + 取消指令
```

## 4.3 Flash 存储器 ECC

NAND Flash 每页通常需要更强的 ECC：
- SLC NAND：BCH(15, 11)，每 512 字节纠 1 位
- MLC NAND：BCH 或 LDPC，每 512 字节纠 8-24 位
- TLC NAND：LDPC，每 512 字节纠 40 位以上

# 五、锁步（Lockstep）处理器

汽车电子（如 ARM Cortex-R5F）广泛使用**锁步模式**：

```
┌───────────────────────────────────────────┐
│  CPU Core 0 ──→ 计算结果 A ──→            │
│                               比较器 ──→  │
│  CPU Core 1 ──→ 计算结果 B ──→  ↓         │
│                               不一致 ──→ 触发安全异常
└───────────────────────────────────────────┘

两个核运行**完全相同**的程序（相同时钟），
输出在每个周期被比较，不一致即为故障。
```

锁步模式的延迟补偿：
- Core 1 可以引入若干周期的延迟，避免同一粒子同时命中两个核
- 典型延迟：2-4 个时钟周期

# 六、性能 vs 可靠性权衡

| 方案 | 面积开销 | 功耗开销 | 检测率 | 纠错能力 |
|------|----------|----------|--------|----------|
| 无保护 | 1× | 1× | 0% | 无 |
| 奇偶校验 | ~1.05× | ~1.05× | 100%（单位） | 无 |
| SECDED ECC | ~1.12× | ~1.12× | 100%（1位）| 纠 1 位 |
| DMR | ~2× | ~2× | 100% | 无 |
| TMR | ~3× | ~3× | 100% | 纠 1 模块 |
| 锁步 | ~2.1× | ~2.1× | 100% | 无（需 SW 恢复）|
