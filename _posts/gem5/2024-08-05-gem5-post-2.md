> gem5 提供了从极简到高度精确的多种 CPU 模型，理解它们的差异有助于选择合适的模型进行研究。

# 一、gem5 CPU 模型概览

| 模型 | 精度 | 速度 | 用途 |
|------|------|------|------|
| AtomicSimpleCPU | 低 | 极快 | 快速功能验证、预热 |
| TimingSimpleCPU | 中 | 中 | 基本时序分析 |
| MinorCPU | 中高 | 较慢 | 有序流水线研究 |
| DerivO3CPU | 高 | 慢 | 乱序处理器性能研究 |
| TraceCPU | N/A | 快 | 基于 trace 的内存系统研究 |

---

# 二、AtomicSimpleCPU

## 2.1 原理

每条指令通过**原子访问（Atomic Access）**完成，无时序模拟：
- 指令执行立即完成（无流水线、无 Cache 时延）
- 访存操作直接完成，返回延迟但不模拟等待周期
- 主要用于**功能正确性验证**和**Cache 预热**

```python
system.cpu = AtomicSimpleCPU()
system.mem_mode = 'atomic'
```

## 2.2 使用场景

- 快速运行长程序，观察程序输出是否正确
- 建立 Checkpoint：先用 Atomic 快速运行到感兴趣的程序段，再切换到 Timing 模型

```bash
# 运行到 1 亿条指令时保存 checkpoint
build/X86/gem5.opt configs/example/se.py \
    --cpu-type=AtomicSimpleCPU \
    --cmd=./benchmark \
    --take-checkpoints=100000000,100000000
```

# 三、TimingSimpleCPU

## 3.1 原理

保持单条指令执行的简单性，但加入**时序模拟**：
- 每条指令按照时序执行（取指、访存有实际延迟）
- 一条指令必须**完全完成**才开始下一条（无流水线）
- CPI 受 Cache Miss 影响，但忽略流水线相关性

```python
system.cpu = TimingSimpleCPU()
system.mem_mode = 'timing'
```

## 3.2 特点

- 比 AtomicSimple 慢约 5-10 倍，但能正确反映内存访问时延对性能的影响
- 适合**内存系统研究**（如分析不同 Cache 配置的效果），但不关心 CPU 微架构细节

# 四、MinorCPU（有序流水线）

## 4.1 流水线结构

MinorCPU 实现了一个**有序的四级流水线**：

```
Fetch1 → Fetch2 → Decode → Execute
  ↕          ↕       ↕        ↕
指令缓冲    指令缓冲  解码缓冲  执行缓冲
```

## 4.2 主要配置参数

```python
cpu = MinorCPU()
cpu.fetch1LineSnapWidth = 0       # 取指对齐宽度
cpu.fetch2InputBufferSize = 2     # Fetch2 输入缓冲
cpu.decodeInputBufferSize = 3     # Decode 输入缓冲
cpu.executeInputWidth = 1         # 每周期最多发射指令数
cpu.executeMaxAccessesInMemory = 2  # 内存访问并发度
```

## 4.3 适用场景

- ARM 嵌入式处理器仿真
- 研究**有序流水线**的冒险处理和 stall 行为
- 功耗建模（面积和功耗比 O3 小很多）

# 五、DerivO3CPU（乱序执行处理器）⭐

## 5.1 微架构结构

O3CPU 实现了完整的乱序执行流水线，与真实处理器高度对应：

```
Fetch → Decode → Rename → Dispatch → Issue Queue
                                           ↓
                              ┌─── IntALU（整数运算）
                              ├─── IntMul（乘除法）
                              ├─── FPU（浮点）
                              ├─── Load（Load Queue）
                              └─── Store（Store Queue）
                                           ↓
                              Writeback → ROB → Commit
```

## 5.2 关键配置参数

```python
cpu = DerivO3CPU()

# 宽度设置
cpu.fetchWidth = 4       # 每周期取指条数
cpu.decodeWidth = 4      # 每周期译码条数
cpu.renameWidth = 4      # 每周期重命名条数
cpu.issueWidth = 8       # 每周期发射条数
cpu.wbWidth = 8          # 每周期写回条数
cpu.commitWidth = 8      # 每周期提交条数

# 缓冲区大小
cpu.numROBEntries = 192  # ROB 容量
cpu.numIQEntries = 64    # 发射队列容量
cpu.LQEntries = 32       # Load Queue
cpu.SQEntries = 32       # Store Queue
cpu.numPhysIntRegs = 180 # 物理整数寄存器数量
cpu.numPhysFloatRegs = 180  # 物理浮点寄存器数量

# 分支预测器
cpu.branchPred = LTAGE()
cpu.branchPred.BTBEntries = 4096

# 功能单元
cpu.fuPool = DefaultFUPool()
```

## 5.3 功能单元配置

```python
# 自定义功能单元池
class MyFUPool(FUPool):
    FUList = [
        # 4 个整数 ALU
        FUDesc(opList=[OpDesc(opClass='IntAlu')],
               count=4),
        # 2 个整数乘除法单元（延迟 3 周期）
        FUDesc(opList=[OpDesc(opClass='IntMult', opLat=3),
                       OpDesc(opClass='IntDiv', opLat=20, pipelined=False)],
               count=2),
        # 2 个 Load 单元
        FUDesc(opList=[OpDesc(opClass='MemRead'), 
                       OpDesc(opClass='FloatMemRead')],
               count=2),
        # 2 个 Store 单元
        FUDesc(opList=[OpDesc(opClass='MemWrite'),
                       OpDesc(opClass='FloatMemWrite')],
               count=2),
    ]
```

# 六、CPU 模型性能对比实验

对 SPEC CPU2006 的 `470.lbm`（内存密集型程序）运行 1000 万条指令：

```bash
# AtomicSimple
build/X86/gem5.opt configs/example/se.py \
    --cpu-type=AtomicSimpleCPU --maxinsts=10000000 \
    --cmd=./lbm
# 运行时间：~2 秒，sim_seconds ≈ 0.011

# TimingSimple（启用 Cache）
build/X86/gem5.opt configs/example/se.py \
    --cpu-type=TimingSimpleCPU --caches --l2cache \
    --maxinsts=10000000 --cmd=./lbm
# 运行时间：~20 秒，sim_seconds ≈ 0.026（Cache miss 影响显现）

# O3CPU（乱序执行）
build/X86/gem5.opt configs/example/se.py \
    --cpu-type=DerivO3CPU --caches --l2cache \
    --maxinsts=10000000 --cmd=./lbm
# 运行时间：~300 秒，sim_seconds ≈ 0.008（乱序掩盖内存延迟）
```

# 七、选择 CPU 模型的原则

| 研究问题 | 推荐模型 |
|----------|----------|
| 功能验证、程序行为分析 | AtomicSimpleCPU |
| Cache 层次结构设计 | TimingSimpleCPU + 精细 Cache 配置 |
| 有序流水线 / 嵌入式处理器 | MinorCPU |
| 乱序处理器参数调优 | DerivO3CPU |
| 内存子系统研究（排除 CPU 影响）| TraceCPU |
| 全系统 / OS 行为研究 | 任意 CPU + FS 模式 |
