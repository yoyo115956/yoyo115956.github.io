> 随着多核处理器核数不断增加，片上网络（Network-on-Chip, NoC）已经成为连接处理器、缓存和 I/O 的主流互连方案。

# 一、为什么需要片上网络

## 1.1 总线的局限性

早期多核处理器使用**共享总线**连接各核，但总线有严重缺陷：
- **带宽瓶颈**：所有核共享同一条总线，带宽随核数增加而紧张
- **可扩展性差**：16 个核以上时，总线电容过大，频率难以提高
- **仲裁延迟**：总线冲突需要仲裁，延迟不确定

片上网络通过**分布式互连**解决这些问题，每对节点可以同时通信，带宽随核数线性扩展。

# 二、NoC 基本架构

## 2.1 三个核心组件

| 组件 | 英文 | 功能 |
|------|------|------|
| 路由器 | Router | 转发数据包，执行路由算法 |
| 网络接口 | Network Interface (NI) | 连接计算节点与网络 |
| 链路 | Link | 路由器间的物理连线 |

## 2.2 拓扑结构

### Mesh（网格）
```
R──R──R──R
│  │  │  │
R──R──R──R
│  │  │  │
R──R──R──R
│  │  │  │
R──R──R──R
```
- **优点**：结构规整，布线简单，局部通信延迟低
- **缺点**：角落/边缘节点连接度低，直径为 $2(\sqrt{N}-1)$
- **典型应用**：Intel Xeon、Tilera TILE64

### Torus（环形网格）
- 在 Mesh 基础上，首尾节点相连，减少直径
- 但跨芯片长线布线困难

### Ring（环形）
```
R──R──R──R──R──R──┐
└──────────────────┘
```
- 结构最简单，适合核数较少的场景（Intel Sandy Bridge 的 LLC 就是 Ring）

### Fat-Tree
- 越靠近根部，带宽越宽（"胖树"）
- 任意节点间通信延迟相同（对称性好）
- **典型应用**：数据中心网络、HPC 互连

### Butterfly / Flattened Butterfly
- 高基数路由器，每个路由器连接多个目标
- 减少跳数，提升带宽

# 三、路由算法

## 3.1 确定性路由

### XY 路由（维序路由）
先沿 X 方向路由到目标列，再沿 Y 方向路由到目标行。

```
源 (1,0) → 目标 (3,2)：
  先 X 方向：(1,0) → (2,0) → (3,0)
  再 Y 方向：(3,0) → (3,1) → (3,2)
```

**优点**：无死锁，实现简单  
**缺点**：不能充分利用所有路径，热点拥塞

## 3.2 自适应路由

根据**当前网络拥塞状态**动态选择路径：
- 监测路由器缓冲区占用情况
- 在多条可用路径中选择最不拥塞的
- **Valiant 随机路由**：先随机路由到中间节点，再到目标（两步 XY）

## 3.3 死锁避免

确定性路由（如 XY 路由）天然无死锁。自适应路由需要额外机制：
- **虚拟通道（Virtual Channel, VC）**：同一物理通道上多路复用，打破死锁循环
- **转弯模型（Turn Model）**：禁止某些转弯方向，打断依赖环路

# 四、流控机制

## 4.1 存储转发（Store-and-Forward）
路由器收到完整数据包后，再转发给下一跳。
- 延迟高（每跳都需完整缓存包）
- 适合大包传输

## 4.2 虫洞路由（Wormhole Switching）⭐
数据包分为 **Flit（Flow Control Unit）**，头 Flit 建立路径后，后续 Flit 流水跟进。
- 延迟低（无需等待完整包到达）
- 缓冲需求小
- **现代 NoC 普遍采用此方案**

## 4.3 虚拟通道（Virtual Channel, VC）
物理链路上多路复用多个逻辑通道，每个 VC 有独立的缓冲队列：
- 解决死锁问题
- 区分不同服务质量（QoS）
- 减少Head-of-Line Blocking（队头阻塞）

# 五、性能指标

| 指标 | 定义 |
|------|------|
| 吞吐量 | 单位时间内传输的数据量（Flits/cycle 或 GB/s） |
| 延迟 | 数据包从源到目的的时间（cycles） |
| 零负载延迟 | 网络空载时的最小延迟 |
| 饱和吞吐量 | 网络开始拥塞时的吞吐量 |
| 功耗 | 链路和路由器的动态/静态功耗 |

## 5.1 延迟模型

$$
T_{total} = T_{router} \times H + T_{link} \times H + \frac{L_{packet}}{BW_{link}} + T_{ser}
$$

其中：
- $H$：跳数（Hops）
- $T_{router}$：单个路由器流水线延迟
- $T_{link}$：链路传播延迟
- $L_{packet}$：数据包长度（Flits）

# 六、RISC-V 多核系统中的 NoC

在基于 RISC-V 的多核芯片中，NoC 主要承担：

1. **缓存一致性消息传递**（MESI/MOESI 协议的请求/响应）
2. **LLC（Last Level Cache）访问**（各核通过 NoC 访问分布式 LLC）
3. **I/O 通信**（CPU 核与外设控制器之间）

### 典型 RISC-V 多核 SoC NoC 设计

```
┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
│ Core 0 │   │ Core 1 │   │ Core 2 │   │ Core 3 │
│ L1 I/D │   │ L1 I/D │   │ L1 I/D │   │ L1 I/D │
└───┬────┘   └───┬────┘   └───┬────┘   └───┬────┘
    │             │             │             │
┌───▼─────────────▼─────────────▼─────────────▼───┐
│              2D Mesh NoC（4×1 or 2×2）           │
└───┬─────────────┬─────────────┬─────────────┬───┘
    │             │             │             │
┌───▼────┐   ┌───▼────┐   ┌────▼───┐   ┌────▼───┐
│ LLC 0  │   │ LLC 1  │   │  DDR   │   │  I/O   │
└────────┘   └────────┘   └────────┘   └────────┘
```
